# Hatoriel iOS Foundation 0.5.0

Native SwiftUI diagnostic application for iOS 16+, adopting approved Crimson Core Minimal colors and procedural red reticle. Respects Reduce Motion and pauses animation outside active scene. Uses the existing headless Rust core, not a rewrite. The Rust static library exports a bounded UTF-8 JSON history API and explicit string ownership/free functions. Swift prepares the context off the main thread and displays the result locally. No inference, server connections, memory persistence, microphone, notifications, attachments, sync or local GGUF runtime in this version. The diagnostic output is prepared context, not an AI-generated response.

## Build
Requires macOS with Xcode, Rust/rustup, XcodeGen and iOS SDKs.
From repository root:
```sh
bash ios/build-core.sh
cd ios
xcodegen generate
open Hatoriel.xcodeproj
```
XCFramework includes arm64 iPhone and arm64/x86_64 simulator libraries. The GitHub macOS workflow runs shared Rust and FFI unit tests and builds unsigned simulator/device .app archives. A physical iPhone requires valid Apple signing and provisioning; the unsigned archive is not an installable IPA. No signing keys are stored in the repository.

## Versioning
Root core/desktop and iOS wrapper: 0.5.0. Android application and JNI wrapper remain 0.4.9 to avoid presenting the iOS foundation as an Android release. Existing Windows/Android functionality remains in place.

## 0.5.1 Native SwiftUI Interface
The diagnostic screen is replaced with a native chat view, animated idle/generation reticle, copy controls, settings sheet, streaming draft, stop, retry and confirmed history clearing. Requires a user-confirmed HTTPS Ollama-compatible server with trusted certificate; no default external server, no plain HTTP, no redirects, no bearer pairing yet. Ephemeral URLSession, bounded NDJSON and terminal-event checks, 300-second resource timeout, request cancellation; client cancellation does not guarantee remote compute stops. Recent context is prepared by Rust before transmission. History is stored in UserDefaults (100 entries / 4 MiB maximum; not separately encrypted and may be included in device backups). Failed/cancelled retries preserve the old answer. Going to background cancels the current request; interrupted partial text is not saved. No local GGUF inference, separate chats, Markdown rendering, memory sync or voice yet. Root/desktop and iOS wrapper 0.5.1; Android remains 0.4.9. CI, native UI rendering and actual server connectivity remain unverified. Existing approved Minimal design retained.

## 0.5.2 Rust Core Integration
Shared `mobile_context` module validates history, modes, trait values, profile and memory bounds, ranks relevant memories, and prepares system context with the existing desktop personality/style/emotion functions. Android JNI now calls the shared module while preserving the JSON array response and default behavior for valid existing inputs. iOS adds a typed context FFI endpoint, four modes, seven personality sliders, dynamic style, opt-in simulated mood, reset, effective trait diagnostics and local preference persistence. Mood is rule-based and updated on request preparation, not an actual feeling or continuous background process. Preferences influence the system prompt sent to the configured server. The shared schema supports profile and approved memory records, but iOS memory/profile editing and storage are still pending; iOS currently supplies empty records/profile. Desktop continues using the same underlying core functions; cross-platform synchronization and database format migration are not implemented. Five shared Rust regression tests added; build and test execution unverified. Root/desktop and iOS version 0.5.2; Android app version stays 0.4.9 although its JNI source now shares the new module. Minimal UI preserved.

## 0.5.3 Local AI Runtime Preview
The iOS app now has an explicit local CPU inference path: pinned llama.cpp b10488 C++ library, statically combined into a separate XCFramework, native C callback API and Swift adapter. It uses the existing prepared Rust messages, model chat template, tokenization, bounded context and greedy sampling (up to 512 output tokens), with streaming UTF-8 chunks, cooperative cancellation and a five-minute deadline. One runtime job at a time; loads/unloads the model for each request. Only decoder-only GGUF chat models with supported built-in templates are intended. No GPU/Metal acceleration, persistent KV cache or model downloads. No automatic fallback to the network. Local mode sends no chat data to the configured server.
The file importer copies a user-selected GGUF into app-private Application Support/Models, excludes the folder from backup, checks magic/minimum length, caps the file at 4 GiB and atomically replaces the previous copy only after a completed copy. This is not full model integrity validation. Profiles Eco/Balanced/Performance use 1024/2048/4096 context tokens and up to 2/4/6 CPU threads, depending on logical cores. Estimated required RAM is model file size +25% +512 MiB +128 KiB per context token; the budget is 40% of physical RAM, not measured process-available memory. Serious/critical thermal states block new local generation. iOS can still terminate the app under memory pressure. Import can take time, cancellation and OOM behavior require device testing.
Build both frameworks before generating the Xcode project: `bash ios/runtime/build.sh && bash ios/build-core.sh`. CI builds device arm64 and simulator arm64/x86_64 CPU slices and packages the llama.cpp license. Source API inspected at tag b10488; compilation, archive linking, runtime model loading, inference, speed and memory usage have not been confirmed. No signed IPA or actual iPhone test yet. Android application remains 0.4.9 and its separate local runtime preview is not integrated. Minimal visual identity retained.

## 0.5.4 Memory & Personality
The iOS MemoryVault stores up to 100 approved records (500 Unicode scalars each), stable integer IDs, timestamps, eight categories and importance 0–100. Native SwiftUI adds creation, editing, search, filtering, deletion confirmation, profile fields (interests, communication, goals, each up to 1000 scalars), duplicate detection and manual approval of one pending rule-based Rust suggestion. Suggestions are session-only, never automatically saved; approved suggestions affect subsequent requests, not an already prepared prompt. The shared Rust engine selects up to 12 keyword-relevant records. Local context use is enabled by default, configurable independently of suggestion generation. Remote memory/profile context is off by default and requires explicit approval for the exact configured endpoint; changing endpoint revokes approval when the vault is available. If the vault cannot be read, its data is excluded from context and editing is blocked instead of overwriting it. Ordinary chat history remains separately transmitted in remote mode, including facts typed in chat; memory consent is not a blanket privacy switch. Vault writes use atomic Data.write with iOS complete file protection and exclude the containing folder from backup; this is OS-level protection, not independent application encryption. A corrupt or locked vault can be retried. Deleting a record does not remove it from previous chat messages or remote server logs. No semantic index, cross-device synchronization, export or automatic migration yet. Two additional Rust FFI tests cover suggestion and no-suggestion paths; actual CI, iPhone UI and storage protection behavior remain unverified. Android app remains 0.4.9. Approved Minimal style retained.

## 0.5.5 Notifications
Native UserNotifications scheduling for up to 40 saved one-shot reminders (1–500 Unicode scalars, 1–10080 minutes). ReminderStore persists a separate atomic, complete-file-protection JSON document excluded from backup. Permission request and app enablement are explicit, disabled by default. Quiet mode/disable cancels pending app reminders and check-ins; future reminders are restored on re-enable, elapsed reminders are not replayed. Optional repeating generic goal check-in at 60–1440 minute intervals; no autonomous AI generation, network calls, push server, background execution or Focus bypass. Text previews off by default; enabling them requires confirmation because the lock screen may reveal text. Sound toggle controls the notification content; iOS controls actual delivery, Focus, sound/vibration and previews. Foreground notification delegate permits banners/list presentation. Tapping a notification uses standard app launch behavior, not a dedicated task deep link. Stored due dates and pending system requests are shown separately; disappearance from pending is not evidence of delivery. Reconciliation on foreground and settings actions repairs missing future requests; saving notification settings resets repeating interval. A locked/corrupt vault is not overwritten and existing system requests are left unchanged. Deleting a record or quiet mode does not clear already delivered notifications. No dedicated Swift unit tests or verified CI/device build yet. Device acceptance checklist: permission denial/revocation, scheduling in foreground/background/terminated app, notification tap, sound and private preview, check-in opt-in, quiet and re-enable, elapsed status, locked storage, date changes, restart, cancellation/deletion and scheduling failures. Android application remains 0.4.9; root and iOS 0.5.5. Approved Minimal identity retained.
