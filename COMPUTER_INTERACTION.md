# Hatoriel v0.7.0 — Computer Interaction Foundation

Base: v0.6.9 commit 6651cd7b97b391d5ee8b9493df076deb0266315d. Windows CI #359, Android #247 and iOS #125 all successful; runtime tests were not executed.

## Local action lifecycle
Computer page (Windows): disabled by default every launch; user opts in for current app session, chooses a typed action, reviews exact scope, confirms once within 60 seconds. Proposal cancelled on leaving page, loss of window focus, busy chat, revocation, or expiry. No reusable approval. No action is invoked by model output, remote bridge or mobile. No new network endpoints or executable command input.
- Inspect local app status: current configured backend/model, portable/installed mode and bridge running state. Does not query model or send contents anywhere.
- Open app data folder in Windows Explorer: only canonical application data directory; no arbitrary path or file opening; rejects UNC/device-prefix paths, rechecks target before launch, fixed Explorer executable, direct argument, no shell. Launch result means process creation requested, not verified Explorer window opened. Drive-letter mapped locations and local OS redirection are not a security sandbox.
- SQLite audit: approval record inserted and bounded to 200 before execution; missing/failed journal blocks action. Outcome updated after attempt; incomplete records may remain after crash or DB failure. Stores timestamp/action/result only, no file contents, paths, secrets or conversation text. Shows newest 30. Not tamper-proof. No logging of rejected or expired proposals yet.

Four desktop regression tests cover session consent, one-shot approval, expiry/revocation, target validation, journal retention and failed journal writes. No new mobile features. CI/runtime testing pending.

## v0.7.1 File System Access (Windows preview)
Session-only read-only grants, up to 8 specific folders selected via native picker. Grant, immediate directory listing and text preview each require explicit one-shot confirmation and pre-execution audit. Revoke clears visible results, pending requests and scoped access. Disable all permissions clears all scopes. No drive-root grants, UNC/device prefixes, relative traversal, alternate data streams, symlinks or Windows reparse-point components. Canonical paths checked before and after reads; regular files only. Up to 200 immediate entries scanned per listing, 64 KiB plain-text preview (UTF-8/BOM UTF-16), no recursion, file mutations, upload, automatic AI access or mobile control. Text is displayed locally, not sent to inference or stored in audit. PDF/DOCX remain supported via existing attachment workflow only. Path checks mitigate common escapes but are not a kernel sandbox; concurrent filesystem mutation/TOCTOU, mapped drive letters and hard links are not fully isolated. File access is synchronous and may stall on slow folders. Three desktop tests and one Unix-only symlink test added; physical-device testing not performed. Previous v0.7.0 CI running when work began; new CI pending.

## v0.7.2 File Search & Navigation (Windows preview)
Base v0.7.1: Windows #361, Android #249, iOS #127 all successful. Explicitly select a granted root and review a frozen filter before one-shot search approval. Recursive worker searches names/extensions, size range, last-modified age and optional case-insensitive literal substring in supported plain-text files (64 KiB max each). Bounded to 4000 scanned entries, 200 results, 64 content read attempts, cooperative 5 seconds between filesystem calls. No persistent index; results sorted by modification timestamp, newest first. Search report marks partial results; directory/metadata errors skipped. Explicit stop, loss of focus, leaving page or revocation cancels and discards results; cancellation is cooperative and individual OS calls may block. Search audit logged before worker starts and on completion, no query or path stored in audit. Results allow separately approved text preview or parent navigation. No automatic AI or remote access, no file writes/transfers. Same scope-check limitations as v0.7.1, including TOCTOU and hard links; no kernel sandbox. No PDF/DOCX content search. Three regression tests added; compilation and real filesystem testing on device pending. Mobile versions updated without desktop capabilities.

## v0.7.3 File Transfer Engine (preview)
Windows explicit confirmed OfferFile action from a scoped file listing/search result. Requires running bridge, audit before reading, regular file <=8 MiB, existing scope checks before/after read, immutable in-memory snapshot, SHA-256, sanitized basename, random 128-bit one-use code, 120-second expiry, one outstanding offer. New offer replaces old. Explicit revoke, scope revoke, session disable and bridge stop clear pending offers. A redeemed offer cannot be revoked mid-response and is consumed even if download fails; prepare again. Existing loopback gateway adds GET /api/transfer, requires existing bearer session key AND X-Hatoriel-Transfer code, no remote paths/list/upload, no cache. Trusted HTTPS reverse proxy required on phone, must forward authorization and custom headers without caching. Any authorized client with both codes can redeem, not device-bound. No automatic file execution or upload. Audit records offer creation, not confirmed delivery. Mobile Android/iOS download with HTTPS, redirects disabled, bounded length, SHA-256 verification, progress and explicit destination picker; Android SAF write may leave partial file if provider fails. No resume, large files, mobile-to-PC, autonomous sending, or physical device validation. Memory snapshot creation synchronous; existing filesystem scope limitations remain. Three Rust store tests; CI pending. Previous v0.7.2 CI running at start.

## v0.7.4 Application Control (Windows preview)
Base v0.7.3 all three CI successful (Windows #363, Android #251, iOS #129). New local session-only catalog: up to 16 user-selected ordinary .exe files, separate audited registration and one-shot launch confirmation. Canonical drive path, existing reparse/symlink checks, MZ header and SHA-256 fingerprint up to 128 MiB; changed executable rejected until explicitly reapproved. Direct process creation with no arguments, no PATH search, no shell or elevation request; common interpreters/system command tools denied by filename, not a complete executable classification. User must trust the software: no signature validation, sandbox, DLL/dependency verification or TOCTOU guarantee. Hashing is synchronous and may pause UI. Tracks up to 8 direct children and polls exit; actual window display not verified, child may spawn independent processes. Revocation/disable clears catalog but does not terminate already launched programs. No forced close, arbitrary arguments, installed-app discovery, remote or AI-triggered launch. Three tests added for name checks, changed file/revocation and invalid headers. New CI and actual process behavior pending. Mobile version alignment only.

## v0.7.5 Screen Awareness (Windows preview)
One-shot, user-confirmed capture of the visible primary monitor using Windows GDI, no added dependency. Existing local session gate, 60s one-use approval and SQLite audit before capture. Bounded source dimensions (4096 each, 16 Mi pixels), top-down BGRA conversion, JPEG max 1920 on longest side, RAM-only snapshot and local preview with detailed pixel view. Capture includes Hatoriel itself and visible private content; other monitors, protected surfaces, HDR, DPI scaling and GPU overlays may be missing or imperfect. Explicit discard, leaving Computer page, lost focus, permission revoke or busy generation clear the Computer preview. User separately adds the snapshot to the existing chat attachment draft; draft survives page change as normal attachment. Vision requires selected local Ollama vision model and explicit send confirmation, existing 1536px normalized image path and no automatic submission. No remote capture endpoint, no screen monitoring, no mouse/keyboard injection, no OS file save. Capture/encoding synchronous, can briefly pause UI. Four tests for size, BGRA, JPEG and one-shot approval; no actual screen/device test. Previous v0.7.4 Windows and Android CI passed, iOS running at start. New CI pending; mobile version alignment only.

## v0.7.6 Clipboard Intelligence (Windows preview)
Three explicit local actions using existing arboard: read text, read image, replace text. Each requires session permission, one-time 60s gate approval and audit before OS access. Text limit 64 KiB UTF-8; rejects NUL/unsupported control characters without truncating. Image RGBA up to 4096x4096 validated after OS/library retrieval, resized to max 1920, PNG <=8 MiB; allocations in clipboard library not prebounded. RAM-only preview; explicit discard and clear on leaving page/focus loss, busy state or permission revoke. Text becomes clipboard.txt attachment for existing reviewed document excerpts; image becomes clipboard.png for existing reviewed local Ollama Vision. No automatic send, no background clipboard collection, no clipboard content in audit. Write text editor freezes an exact snapshot for confirmation; overwrites system clipboard, no simulated paste or execution. Windows clipboard history/sync or other applications may retain content; Hatoriel does not control OS retention. Existing ordinary Ctrl+V and explicit chat copy/paste remain unchanged. No remote clipboard access, image writing, file-list clipboard support, or mobile clipboard automation. Four tests added for bounds, encoding and one-shot actions; previous v0.7.5 CI in progress at start, new CI/runtime validation pending. Mobile versions aligned only.

## v0.7.7 Desktop Automation (Windows preview)
Session-only typed workflow editor, up to 8 steps. Add an existing reviewed action to the plan instead of executing it; show exact target/filter/clipboard text, reorder upwards/remove, start reviewed plan, then advance one step at a time through the existing one-shot 60s approval gate. Supports inspect status, open app data, list/read/search scoped files, launch approved apps, capture primary screen, clipboard text/image read and reviewed text write. Permission changes and file transfer offers intentionally excluded; no AI-generated steps, commands, loops, scheduling, remote control or background execution. Each step individually audited and revalidates existing scopes/app fingerprints at execution; async search waits for worker completion before advancing. Failures, expired/cancelled approval, focus loss, leaving page, chat busy, revoke or stop clear the plan and cancel outstanding search cooperatively. Completed effects cannot be rolled back; no forced termination of launched apps. Results appear in existing UI, no automatic output chaining. Screen/clipboard previews added to chat only through explicit normal attachment flow. Plan text retained only in RAM; normal OS clipboard retention applies. Four pure workflow regression tests. v0.7.6 hotfix CI still running at start; compilation/device behavior pending. Mobile version alignment only.
