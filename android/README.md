# Hatoriel Android 0.4.9 — Stability Preview
Native ARM64 Android chat using the shared Rust prompt/context core through JNI. Java transport uses Ollama /api/chat (streaming NDJSON) with a user-selected endpoint. Default is http://127.0.0.1:11434, which refers to the Android device itself, not the user's PC. No runtime or model is bundled. A working compatible server is required. HTTP is allowed only on loopback; external servers must use HTTPS with a trusted certificate. Redirects are disabled. Configure and confirm the endpoint before sending. Recent history and user message are transmitted to that server; server-side retention is outside this application's control.
History is stored in private SharedPreferences, limited to 100 messages. No encryption beyond Android storage protections; no backup or cross-device sync. History can be cleared with confirmation. The UI supports cancellation of client requests, but does not guarantee cancellation of server computation. Since 0.4.6, rotation can retain the process-local session; stopping the activity cancels foreground-only requests, while opted-in background generation may continue. Process death interrupts generation. The submitted user message remains in history.
Build: Android API 26+, ARM64, SDK 35, Java 17, Gradle 8.9, AGP 8.7.3, NDK 27.2.12479018. GitHub Android CI produces Hatoriel-Android-ARM64-Debug on success. No Gradle wrapper or release signing yet. See workflow for native library packaging steps.
Next: rich Markdown, conversation management, lifecycle persistence, bundled local inference, mobile memory, authenticated desktop connectivity, device tests. No production-ready release yet.
Version 0.4.1: dark black/burgundy styling, live response preview, long-press copy, retry of the last request, and haptic feedback after completion (subject to device settings). Retrying an existing answer requires confirmation and removes the old answer before requesting a new one. Partial replies are not persisted. Full redesign, light theme, sound effects and Markdown formatting remain pending. See DESIGN_DIRECTION.md.


## 0.4.2 runtime preparation
Separate Android runtime CI builds llama-server for ARM64 from pinned llama.cpp tag b10488 with CPU-only portable settings. The runtime artifact is experimental, separate from the APK and not launched by the application yet. Build and device execution remain unverified. Model import uses the Android document picker, copies into private storage with a temporary file, checks GGUF magic and minimum size, bounds file size to 8 GiB, and replaces the prior model only after successful copy. This does not validate tensors, architecture or RAM requirements. Existing Ollama chat remains unchanged. Next: integrated local inference, runtime lifecycle, RAM limits, and device tests. Full design changes require approval per DESIGN_DIRECTION.md.

## 0.4.3 mobile memory
Approved memories (up to 100, 500 Unicode characters each), categories, importance, duplicate checks, deletion and editable profile stored in private SharedPreferences. Suggestions use shared Rust keyword rules and require confirmation. Memory/profile use in model context is off by default; enabling it explicitly authorizes sending selected memories/profile to the configured server. The first response after a suggestion may not use that newly approved memory because the context snapshot is built before approval. Keyword ranking only; no encrypted storage, cross-device sync or semantic mobile index yet. Android JNI host test verifies relevant memory selection. Crimson Core avatar concept approved, full UI redesign still awaiting separate approval. CI execution and device behavior not verified.

## 0.4.4 device and model manager
Reports Android device/SoC, available logical processors, ARM64 support, total and available RAM, private storage capacity, thermal and power-save status. Model size and RAM budget are compared using a conservative heuristic (file size + 25% + 512 MiB + 128 KiB per context token); the budget subtracts the larger of 768 MiB or 1/8 total RAM from currently available RAM. These values are estimates, not validated compatibility or measured model requirements. Eco/Balanced/Performance profiles save suggested CPU threads and context sizes (1024/2048/4096 tokens), not active inference settings yet. Supports removing the private imported GGUF copy with confirmation, while preserving the original file. No actual local inference, multi-model library or device benchmark in this version. The approved design gate remains unchanged. CI and on-device execution unverified.

## 0.4.5 Android notifications
Local one-shot reminders (1–10080 minutes, up to 100 records) saved in private SharedPreferences. Delivery is opt-in and uses an inexact AlarmManager alarm with a private broadcast receiver. Android 13+ requests POST_NOTIFICATIONS permission. Reboot/package replacement restores scheduling; force-stop and OS battery restrictions can prevent or delay delivery. Quiet mode cancels pending alarms until disabled; it does not change system-wide Do Not Disturb or erase existing notifications. Notifications open the main chat, use private lock-screen visibility and a dedicated channel with system-managed sound/vibration. No exact-alarm permission, persistent service, remote AI calls, automatic goal check-ins or cross-device sync. Delivery and compilation remain unverified on devices. The full UI redesign approval gate still applies.

## 0.4.6 background generation preview
A process-local generation session survives Activity recreation; completed responses are persisted before notifying the UI. User may opt into continuing an already initiated network request when the app is minimized. Foreground dataSync service displays an ongoing notification with stop/open actions, ends when the request ends, and never starts itself at boot. No new inference request is initiated by the service. Background mode is disabled by default, falls back to foreground-only with Android battery saver or missing notification permission, and has a cooperative five-minute cancellation deadline. OS process death/force-stop interrupts requests; no recovery of unfinished streams or guaranteed cancellation of remote computation. This is network inference only, not integrated GGUF runtime. Service lifecycle, Android 15 restrictions and build/device behavior are not yet verified. Full UI redesign requires separate approval.

## 0.4.7 desktop connectivity preview
Optional HTTPS-only bearer session key for the loopback Windows Ollama bridge. Requires a separately configured trusted HTTPS reverse proxy/private network; no automatic discovery, device pairing or sync. See ../DESKTOP_CONNECTIVITY.md for setup and limitations. No build or cross-device test confirmed.

## 0.4.7 stabilization patch (pre-redesign)
Retry now preserves the previous assistant message until a replacement is successfully generated and committed, and leaves it unchanged on cancellation or failure. Changing endpoint disables memory-context sharing until explicitly re-enabled. Session deadline callback is removed after completion and timeout status is retained. Final NDJSON line is checked against the response bound. Stop notifications carry a generation-specific ID, and stale stop actions are ignored. Foreground mode checks system notification availability. No UI redesign or version bump; full concept approval pending. These changes were reviewed statically; push-triggered CI results were not available through the connector.

## 0.4.8 Crimson Core Minimal
User-approved Minimal concept implemented as native theme, procedural reticle view, app icon, neutral graphite chat surfaces, compact bottom navigation, and independently scrollable connection settings. Existing memory, models, reminders and bridge controls remain accessible; Android still has one conversation history and no integrated local inference. Windows uses matching dark theme, reticle in navigation/empty chat/floating avatar, and red tray icon. Idle and active generation are wired; voice and additional emotional states are not. This is a native implementation of the approved direction, not a pixel-identical rendering of the concept art. CI and visual/device verification remain pending.
